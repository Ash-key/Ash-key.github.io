bash脚本和sh脚本有什么区分？
在 Ubuntu/Debian 等系统中，/bin/sh 默认指向 dash（一个极其严格遵循 POSIX 标准、但功能极少的轻量级 Shell），而不是 bash
bash init.sh nemu
这样写不用chmod +x /usr/bin/bash本身是具有+x权限的可执行文件,仅仅读入nemu
另外souce xx执行文件，这样在本shell内执行，而不是像普通执行一样在子shell内执行，source简写为. 注意空格和/区分普通执行
source xxx/xxx.sh 等于 . xxx/xxx.sh 都是source执行
./xxx/xxx.sh 普通执行 ./
用了source,我才能在本shell中成功引入临时环境变量，否则是在子shell中发生引入进而无效
经常在.bashrc文件修改完环境变量后执行source ~/.bashrc ，是为了在当前终端执行引入环境变量，而不用重新打开一个终端由系统执行

以前只输入make而不接任何东西时，调度员会去任务清单（Makefile）里找第一个出现的任务来执行。在大多数 C/C++ 项目中，Makefile 的第一个任务通常是 all。所以，你输入 make，实际上相当于输入了 make all。这个任务通常负责把整个项目编译成可执行文件

当你输入 make menuconfig 时，你是在明确告诉调度员：“不要执行默认的第一个任务，我要执行清单上名为 menuconfig 的那个特定任务。”

这个项目是怎么实现自动跟踪，防止学生粘贴代码的？在项目ics2024的的Makefile文件中，有着一段自动化行为，每当make成功一次，就会自动commit一次，产生对应的git log日志，如此跟踪开发进程,同时自动存档开发历程，方便回档；同时，这种自动的提交和手动提交书区分开的，用git log –author=21312677筛选出手动提交的记录，自动追踪的垃圾信息由此看不见了
手动提交的时候往往已经和上一次自动提交没有区别，所以需要允许空提交
git add.
git commit –allow-empty
