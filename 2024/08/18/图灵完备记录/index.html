图灵完备记录

cpu设计思路
能够输出中间态的元件真是一个重要的东西
第一核心：
首先，我需要一个核心组件，全加器，其实就是三个输入两个输出的元件，输入进位与两个比特位，输出对应比特位和进位，有了这个就能组合出8位甚至64位加法器件
一个非常有趣的观察二进制数的角度，包括原码和补码，把每一位看作一个是十进制数字，数字表达的值就是所有位之和，补码的记忆与使用也更加简单
源码:
128 64 32 16 8 4 2 1
0 0 0 0 0 0 0 0

补码：
-128 64 32 16 8 4 2 1
0 0 0 0 0 0 0 0
不需要特别的处理，第一核心已经可以进行补码计算，即加减法已经搞定
图灵完备中不允许使用同步环路，也就是说我搭载不出经典的RS触发器用于存储东西，官方给出来的方案是使用延时器，用了延时期间就可以用RS这样的了

我现在玩的这个看起来是比较差的版本，ui更加差劲，同时设计的地方让人不舒服，比如说我制造出了1位，8位存储器（这里送了64位存储器）后，little box这一关应该用的是8位存储器，好的版本是，而我的版本用的64位存储器

第x核心：
寄存器堆；实现寄存器移位8 位指令mov source,destination;xx(指令码) xxx(源头) xxx(目标), 6个8位寄存器和一个输入寄存器，一个输出寄存器，输入寄存器和6个寄存器堆与源头地址编码，占用地址7/8，输出寄存器和6个寄存器堆编码，这样可以在指令中制定从谁往谁进行复制操作

第x核心：
counter计数器

第x核心：
ALU单元
默认reg1 reg2 reg3

第x核心：
完整alu单元：
寄存器单元和alu单元合体
同时，合体时，关于指令，先只关注alu和move指令，忽略掉immediate和condition,

第x核心：
条件判断，对满足的条件，返回真，包括>0 <0 >=0 <=0 =0 =0 never always(这两个什么用处？)

第x核心：
立即数，这个不是核心，是在完整alu单元上直接绘制,将指令中的立即数直接放入reg0,6位都给立即数使用

第x核心：
用raw元件替换关卡自己提供的指令输入
这一步反而是我需要提前的，只要一开始就制作好这个，才能在之前的指令工作中进行测试工作，由计数器驱动raw

turingcomplete不是我制造的关键组件，现实中都非必要：
1：延迟线，这个是作者给的，无法搭建出来的东西，用延迟线搞定rs触发器的功能实现寄存器存储，在实际世界中我使用回环电路实现触发器进而实现寄存器
2：开关，也就是三态门，开关为假时输出中间态，在logism中教学cpu我可以选择使用大量mux多路选择器解决这个问题,实际世界中使用三态门,三态门总线结构简洁

第x初核心（没有三态门的情况）：
mux数据选择器，纯逻辑门搭建,图灵完备中倒翻天罡用switch搭mux,这个我已经用纯粹的逻辑梦搭建出来了

第x初核心：
分线器和集线器，结构简单的东西，但是是基础部件无法替代

解码器-二进制数字解码为多个灯，选择某一位为真，3-8解码器，禁用高位，可以实现1-2解码器，2-4解码器；多位选择器mux,多选一，选择某一位输出

最后一件事：
把前面的设计和条件判断核心合体，其实就是控制单元；这个跳转行为在硬件和软件上的表现如下：硬件上，将reg3作为待判断的值，利用condition指令中的指令码对reg3做判断，然后输出真假，为真，则执行擦写操作，counter暂停一次计数，并把计数值改成reg0中的值；软件上，我要做两条操作指令： mv reg0,填入想要去的地址;判断reg3（自动擦写counter,并开始执行跳转的程序）

如此，我有了一个图灵完备的cpu,可以执行所有程序，我再把这个东西简介整理

立即数那一章，我找不到的问题原来是，在立即数模式下没有禁用对指令复制模式下的3-8译码器，机器用三八译码器把立即数解析为某两个寄存器的读写控制位，导致某些寄存器被立即数意外的开启，造成问题

overture汇编语言中，label功能没有对应的跳转功能，而是把label的行号（label不占行号，内部值记录下一行代码的行号）赋予reg0,之后在condition指令前写albel,再使用condition指令就可以条件或无条件跳转到此处,这样我就不用计算行号再赋予reg0再跳转

需要注意的是，非常有趣的地方，写汇编没有堆栈之类的管理结构，调用函数后，我这里的寄存器不会自动恢复，尤其是用于判断的和用于地址跳转的reg0和reg3,容易不察觉，
我可以编写一段通用复制程序，把需要恢复但同时需要用的寄存器的值进行复制，在返回主函数前再恢复

走迷宫问题，对完美迷宫，用右手法则一定能走出去

overturn架构还是太掉头发了，升级leg架构

非常需要注意的，有符号数和无符号数的溢出，CF是无符号数溢出，就是全加器的简单的二进制判断，但是有符号数字的溢出时全加器判断不出来的，比如8位cpu中，127+1,这个计算不会报出任何进位溢出，但是计算的结果是有符号数字-128，毕竟8位cpu有符号数字没有+128，范围-128到127，这里的计算错误需要额外的异或电路判断以报错OF
这是现代cpu的两个标志位

加法器溢出，不一定有符号计算错误，77与-76
加法器不溢出，不一定无符号计算错误，如127和1

我现在的溢出检测方法（未完全确定），异或检测输入符号位，真则说明异号相加，溢出无效直接忽略；假则说明同号相加溢出有效应该注意

我没有明白挂面关卡前一关中宽指令关卡的作用，他实现了：两个时钟周期输出两条指令，挂面关卡直接更改成了一周期4指令

有了挂面关卡一周期四指令，现在我可以不用受之前add指令的约束，现在可以随意两个寄存器或输入相加，存储到随意一个寄存器或输出,不用不停的移动寄存器

这里的宽指令设计很好，前两位任然空出来不用，使得我可以直接复用之前立即数的设计，完成6个条件指令后可以免费获得他们的立即数版本,但是这时候会发现addi会对应有两种指令码的，分别是1号或2号参数作为立即数，或许应该取名addi2,当然更好的汇编器可以自动对addi划分两种SDFGHJKL
leg架构消灭了单独的immediate和copy指令，现在只有两种逻辑计算（00），条件（10）同时，leg只有宽指令
但是要注意，条件指令的第三个参数只能是数字地址，不能是制定寄存器，真是非常的无语

现在要弄个用于存储的存储器（内存）出来，我的思路是，增加一个仅有输出的寄存器，现在的输出，0-5寄存器，6计数器，7输出端，现在为内存增加8寄存器，调用刷写时先用add刷写8寄存器地址，然后再用add将数据送入内存，这样我需要在为内存制定一个调用地址，9,即占用8和9，两个步骤：写内存，读内存到寄存器或输出，如下
写内存：
add 地址reg1 0 寄存器8
add 数据reg2 0 9（调用内存）

读内存：
add 地址reg1 0 寄存器8
add 9（调用内存）0 输出7

很好，用这个思路成功通过了

对所使用的8bit寄存器，其就算是永久输出的端口，其数据也会在刚刚更新后的下一个时钟周期才会更新，也就是说有，我可以用命令addi reg1 0 reg1，来去同一个

关键组件栈
你知道的，函数嵌套调用天生就是一个栈的结构，这就是为什么大多数架构硬件上提供栈结构
有四个端口，pop单bit,push单bit,单字节数据data，输出
我的实现，把栈当作特殊的寄存器，占用地址reg10,不过这个寄存器的性质和其他寄存器不一样,push端口连接写4号位，pop端口连接读的2号和3号位
4-16解码器真是实用啊，拓展内存和栈直接就拿来用了

关键扩展-函数调用指令call和ret
完成这个拓展，这次不占用预留的占用地址reg10地址，而是占用预留的指令集，同时，完成call和ret需要限制在一个周期，确保下个周期就是函数或主函数的指令
注意到，我用5和6两个位作为区分指令类型的位，有00（alu指令占用），01（未占用），10（条件指令占用），11（未占用）
现在用11作为call和ret的类区分
call 00110000 用程序计数器count值+4,压入push存储
ret 00110001 pop弹出值并写入程序计数器count

因为leg指令每次取出32位的宽指令，同时指令码是8位的，是伪32位处理器，所以这两个指令使用格式我设计如下
call null null func_addr
ret null null null

现在不用考虑在call ret指令下禁止掉栈联通的参数2和参数3的通路，因为使用时用的是null,导致不会选中栈的地址11号，只会选中reg0,注意到alu的输出被op的00控制着，所以输不出来，同时这也是处理器的硬件漏洞，加入软件编写不按照规则，写成call reg11 reg11 func,会导致总线中有这样的数字在本周期末端流通，当然虽然会输入alu和condition发生计算,但是输不出来,因为输出用开关控制了一下
